# Development Instructions for AI Agents - Purchase Microservice

> Guidelines for AI-assisted development on the Spring Boot Purchase Microservice.

## 🎯 Project Overview

- **Purpose**: REST API for purchase order management
- **Type**: Spring Boot Microservice
- **Tech Stack**: Java 17+, Spring Boot 2.7+/3.x, Maven, JPA/Hibernate
- **Build**: Maven with Spring Boot plugins

---

## 🏗 Architecture Pattern

**Layered Architecture** with clear separation:
- **Controller**: HTTP request handling, routing
- **Service**: Business logic, validation
- **Repository**: Data persistence via JPA
- **Model/Entity**: Domain object mapping

### Core Layers
```
HTTP Layer       - REST endpoints in @Controller classes
Service Layer    - Business logic with @Service annotation
Repository Layer - Data access with JpaRepository
Model Layer      - @Entity classes with JPA annotations
DTO Layer        - Request/Response objects
```

---

## 📂 File Naming & Conventions

**Controllers**: PascalCase with `Controller` suffix
- `PurchaseController.java`, `PaymentController.java`

**Services**: PascalCase with `Service` suffix
- `PurchaseService.java`, `OrderService.java`

**Repositories**: Interface extending `JpaRepository`
- `PurchaseRepository.java`, `PaymentRepository.java`

**Entities**: PascalCase with `@Entity` annotation
- `Purchase.java`, `Order.java`, `Payment.java`

**DTOs**: PascalCase with `DTO` suffix
- `PurchaseDTO.java`, `PaymentDTO.java`

**Methods**: camelCase
- `findById()`, `createPurchase()`, `validatePayment()`

---

## ✅ DO's

1. **DO** use @Transactional for database operations
2. **DO** implement validation in Service layer
3. **DO** use ResponseEntity for flexible HTTP responses
4. **DO** separate business logic from HTTP concerns
5. **DO** implement custom exceptions for domain errors

---

## ❌ DON'Ts

1. **DON'T** access database directly from controllers
2. **DON'T** expose entity objects in HTTP responses (use DTOs)
3. **DON'T** handle transactions in controllers
4. **DON'T** hardcode database queries (use JpaRepository methods)
5. **DON'T** mix business logic with HTTP status codes

---

## 📋 Common Workflows

**Adding a new REST endpoint**:
1. Create entity model: `Order.java` with JPA annotations
2. Create repository: `OrderRepository extends JpaRepository`
3. Create service: `OrderService` with business logic
4. Create DTO: `OrderDTO` for API contract
5. Create controller: `OrderController` with @GetMapping, @PostMapping
6. Write integration tests

**Database operations**:
1. Define entity with @Entity, @Table, @Id
2. Add custom @Query methods in Repository
3. Call repository from Service
4. Implement error handling (EntityNotFoundException, etc.)

**Adding health checks**:
1. Add dependency: `spring-boot-starter-actuator`
2. Implement `HealthIndicator` interface
3. Return Health.up() or Health.down()
4. Access at `/actuator/health`

**Generating API documentation**:
1. Add `springdoc-openapi-ui` dependency
2. Annotate endpoints with @Operation, @ApiResponse
3. Access at `/swagger-ui.html`
